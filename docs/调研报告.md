# 调研报告：Minecraft 跨整合包按键同步

本文是动手写代码之前做的调研，回答两个问题：

1. **已经有哪些方案？**（避免重复造轮子）
2. **底层文件格式到底是什么样？**（避免踩坑）

> 调研时间：2026 年。所有结论尽量附出处链接。
> 标注说明：**【源码】**=读过 Minecraft/启动器源码；**【实测】**=读过真实的 `options.txt` 文件；
> **【Wiki】**=Minecraft Wiki；**【文档】**=官方帮助文档。

---

## 一、结论先说

1. **已有的 Mod 方案全都要求「每个整合包都装这个 Mod」**，没有任何一个能免装 Mod。
2. **游戏外的独立工具几乎不存在**。GitHub 上连一个成熟的 `options.txt` 编辑器都找不到，
   更不用说「扫描多个实例 → 智能匹配同 Mod 按键 → 一键推送」的工具。**这是空白点。**
3. 唯一做过「跨 Mod 同功能配对」的是 **Just Universal Keybinds**（2026 年新 Mod，约 1.2 万下载，
   闭源、无仓库），它证明了这件事可行，但形态仍是「装 Mod」。
4. **关键技术事实**：`options.txt` 里按键的绑定名 = `key_` + 翻译键。
   **绑定名相同 ⇒ 功能相同**，所以「同一个 Mod 的按键」天然能精确匹配，根本不需要 Mod 参与。
   只有「不同 Mod 的同类功能」才需要人工映射表。
5. 最大的技术地雷是**版本与加载器差异**：
   - 1.12 及更早用**数字键码**（`key_key.jump:57`），1.13+ 用**命名键码**（`key.keyboard.space`）
   - 1.12 里**鼠标键是负数**（左 `-100` / 右 `-99` / 中 `-98`）
   - **Fabric 不支持修饰键组合**，同一个 Mod 在 Forge 上是 `Ctrl+J`、Fabric 上默认就是 `M`

### 它们的共同空白

| 能力 | 现状 |
|---|---|
| 无需在每个整合包装 Mod | ❌ **全都要装**，游戏外工具**根本不存在** |
| 一键推送到**多个已有实例** | ❌ Prism 只在「新建实例」时复制；Default Options 只在「首次启动」生效；Global Options 是永久共享一份 |
| 跨启动器 | ⚠️ 只有 Just Universal Keybinds 声称支持（但仍要各包装） |
| 智能匹配「不同 Mod 的同类功能」 | ⚠️ 只有 Just Universal Keybinds 做了，闭源、不可复用 |
| 只动按键、不碰其他设置 | ⚠️ Configured Defaults / Options Enforcer / UnifiedOptions 有思路，但都是 Mod 且面向整合包作者 |
| 处理 Fabric 无修饰键 | ❌ 无人处理 |
| 处理 1.12 数字键码 ↔ 1.13+ 命名键码 | ⚠️ 只有 UnifiedOptions 的 1.12 版做过单向转换，已停更 |

**本项目的定位**就是补这几个空白：**不装 Mod + 跨启动器 + 智能匹配同 Mod 按键 + 一键推送多个已有实例。**

## 三、`options.txt` 格式规格

### 3.1 解析规则

来自 `Options.java`（1.20.1 / 1.21.11 / 26.2 三版一致）：**【源码】**

```java
private static final Splitter OPTION_SPLITTER = Splitter.on(':').limit(2);
// ...
BufferedReader reader = Files.newReader(this.optionsFile, Charsets.UTF_8);
reader.lines().forEach(line -> {
    Iterator<String> it = OPTION_SPLITTER.split(line).iterator();
    compoundTag.putString(it.next(), it.next());   // 抛异常的行被 "Skipping bad option" 丢弃
});
```

要点：

* 单行 `名字:值`，**只切第一刀** —— 值里的后续冒号保留（这就是 Forge 的 `:SHIFT` 能存活的原因）。
* **UTF-8 无 BOM**。
* 写文件用 `PrintWriter.println` → **Windows 上是 CRLF**；实测文件**以换行结尾**。**【实测】**
* **保存是整文件截断重写**（`new FileOutputStream`），而且**只遍历自己认识的 `OptionInstance` 与 `keyMappings`**
  → **未知行、其他工具写的自定义行会在下次保存时全部丢失**。

### 3.2 按键行

```
key_<KeyMapping.getName()> : <键值> [ : <修饰键> ]
```

* 前缀**恒为 `key_`**，后面**原样**接 `KeyMapping` 的 `name`。**【源码】**
* 约定俗成 `name` 是翻译键，即 `key.<modid>.<动作>`：`key_key.jei.showRecipe`。**【实测】**
* **但 `name` 可以是任意字符串**，实测反例：
  * `key_iris.keybind.reload` → name 是 `iris.keybind.reload`
  * `key_gui.xaero_open_map` → name 是 `gui.xaero_open_map`
  * `key_create.keyinfo.toolmenu`、`key_hotKey.fxntstorage.toggle_backpack`、
    `key_ftbultimine.change_shape.next`、`key_placebo.toggleTrails`、`key_ponder.keyinfo.ponder`
  * 1.12 时代更极端：`key_Change Caster Focus`（含空格、无命名空间）**【实测】**

  → **结论：绝不能靠切分绑定名来推断 modid。** 必须去读 Mod 的语言文件（本项目的做法），
  或者干脆只把「绑定名字符串」当作跨实例匹配的主键。
* 一个动作**只能绑一个键**，没有 `key.keyboard.w,key.keyboard.up` 这种写法。**【源码】**
* 修饰键后缀（`key.keyboard.o:CONTROL`）是 **Forge / NeoForge 的扩展**，
  原版 `InputConstants.getKey()` 遇到它会抛异常。**【源码】**

### 3.3 键值语法

* 命名空间：`key.keyboard.*`（键盘）、`key.mouse.*`（鼠标）、`key.scan.*`。
* 未绑定 = `key.keyboard.unknown`。
* 鼠标：`key.mouse.left` / `right` / `middle`，第 4 个键起是 `key.mouse.4`、`key.mouse.5`…
* 也可以写十进制整数（`key.keyboard.1234`）；**不认识的字符串会让游戏抛 `IllegalArgumentException`**。
  → 工具写之前必须自校验。**【源码】**

### 3.4 真实样例（本项目在一台真实机器上读到的）

```text
lang:zh_cn
fov:0.0
guiScale:3
...
key_key.attack:key.mouse.left
key_key.sneak:key.keyboard.left.shift
key_key.sprint:key.keyboard.left.control
key_iris.keybind.shaderPackSelection:key.keyboard.o
key_key.jei.toggleOverlay:key.keyboard.o:CONTROL
key_key.jei.transferRecipeBookmark:key.mouse.left:SHIFT
key_gui.xaero_open_map:key.keyboard.m
key_gui.xaero_instant_waypoint:key.keyboard.keypad.add
key_create.keyinfo.toolmenu:key.keyboard.left.alt
key_hotKey.fxntstorage.toggle_backpack:key.keyboard.b
```

实测统计：**285 行、179 个按键、CRLF 换行、UTF-8 无 BOM、末尾有换行、185 个 Mod jar。**

### 3.5 非按键条目

* **过滤只需要一条规则**：`line.startswith("key_")` → 按键行；其余原样保留。
* 命名族：`soundCategory_*`（音量）、`modelPart_*`（皮肤部件）、其余为单值选项。
* ⚠️ **`fov` 不是角度**，是归一化 double：`0.0`=70°、`0.5`≈90°、`1.0`=110°、`-1.0`=30°。**【源码】**
* 野生文件里有 `chatDelay: 0.0` 这种冒号后带空格的脏数据 → 解析时要 `Trim()`。**【实测】**

### 3.6 版本差异

| 版本 | 变更 |
|---|---|
| ≤1.12.2 | 键值是 **LWJGL 整数**；鼠标是**负数**（`-100` 左 / `-99` 右 / `-98` 中）；Mod 键名是英文原名 |
| 1.10 | 新增 `version:` 行；**缺这一行的话文件会被重置为默认** |
| 1.13 | 键码改为 `key.keyboard.*` / `key.mouse.*` 命名体系 |
| 1.16 | `key_key.swapHands` 改名 `key_key.swapOffhand` |
| 1.21.9 / 1.21.11 | 键位系统重写（`KeyMapping.Category` 用 Identifier）；调试键变为可绑定 |
| 26.2 / 26.4 | 新增 `key_key.friends`；`socialInteractions` 计划由 `otherPlayers` 取代 |

**按键一直没有搬到别的文件** —— 到 26.2 为止都还在 `<游戏目录>/options.txt`。

### 3.7 OptiFine 的 `optionsof.txt`

**里面也有按键行，而且用的是旧式数字键码**：**【实测】**

```text
key_of.key.zoom:46
```

1.12.2 的整合包甚至会在 `options.txt` 和 `optionsof.txt` 里各写一份 `key_of.key.zoom:46`。
所以装了 OptiFine 的实例，这是一份**独立的第二数据源**，需要单独处理。

### 3.8 1.12 数字键码 ↔ 1.13+ 命名键码

几个**最容易错**的点：

| 事实 | 说明 |
|---|---|
| 鼠标键是**负数** | 左 `-100` / 右 `-99` / 中 `-98`。`key_key.drop:211` 里的 `211` **不是鼠标键**，而是 LWJGL2 的 **Delete**（`KEY_DELETE = 0xD3 = 211`） |
| 旧版 `0` = **未绑定** | 而新版的 `key.keyboard.0` 是**数字 0 键**（旧版数字 0 键是 `11`）。语义完全相反 |
| F11/F12 是 **87/88** | 与 F1–F10（59–68）**不连续** |
| F19 是 **113** | 不是 106，中间被 KANA(112) 占用 |
| 小键盘小数点 | 旧版 `KEY_DECIMAL = 83`；1.13~1.25 叫 `key.keyboard.keypad.period`，**26.3 起才叫 `keypad.decimal`** |
| 反向斜杠 | 旧版 `43` 无法区分 ANSI 与 ISO 反斜杠；新版后者叫 `key.keyboard.world.1` |

本项目内置了完整对照表（`mcsync/legacy_codes.py`），
**无法确定的键码（如日文键盘专有键）会跳过并报警，而不是猜一个值写进去。**

## 四、各启动器的实例路径

| 启动器 | 默认位置 | options.txt 在哪 |
|---|---|---|
| **PCL2** | 自定义（存在 `PCL/config.v1.yml` 的 `LaunchFolderSelect`，`$` = PCL 程序目录） | **版本隔离开** → `.minecraft/versions/<版本>/options.txt`；**关** → `.minecraft/options.txt` |
| **HMCL** | `%APPDATA%\.minecraft` | 同上，由「全局版本隔离」决定 |
| **官方启动器** | `%APPDATA%\.minecraft` | `launcher_profiles.json` 里每个 profile 的 `gameDir` |
| **Prism / MultiMC / PolyMC** | `%APPDATA%\PrismLauncher\instances\<名字>\` | `minecraft/options.txt`，没有则 `.minecraft/options.txt`（**两种布局都要探测**） |
| **CurseForge** | `%USERPROFILE%\curseforge\minecraft\Instances\<名字>\` | 实例目录下 |
| **Modrinth App** | `%APPDATA%\ModrinthApp\profiles\`（0.8.0 前叫 `com.modrinth.theseus`） | 实例目录下 |
| **ATLauncher** | `%APPDATA%\.ATLauncher\instances\<名字>\` | 实例目录下 |
| **GDLauncher** | `%APPDATA%\gdlauncher_carbon\data\instances\<名字>\` | 实例目录下 |

### PCL2 的版本隔离算法（源码级）**【源码】**

PCL2 的 `PathIndie` 属性决定 options.txt 的位置，判定优先级是：

1. 老的每版本设置 `VersionArgumentIndie`（1 = 开 / 2 = 关）
2. **版本目录下有 `mods\`（且有文件）或 `saves\`（且有目录）→ 自动开启隔离**
3. 全局默认 `LaunchArgumentIndieV2`：`0` 关闭 / `1` 仅隔离可装 Mod 的版本 / `2` 仅隔离非正式版 /
   `3` 两者 / 其他 = 隔离所有版本

PCL2 启动日志里会打印 `版本隔离：<布尔>`，第三方工具也能读。
**本项目的做法更简单也更稳：两种情况都探测，谁有 `options.txt` 就列谁。**

### 版本号与加载器怎么读

* **MC 版本**：版本 JSON 的 `clientVersion` 字段（NeoForge 生成的 JSON 里就是 `1.21.1`），
  退化到 `inheritsFrom`，再从目录名里正则匹配 `1.xx.y`。**【实测】**
* **加载器**：版本 JSON 的 `libraries` 里找 `net.neoforged` / `net.minecraftforge` / `net.fabricmc` / `org.quiltmc`；
  读不出来就统计 `mods/` 里各加载器的 mod 元数据文件数量。

## 五、写文件的安全要求

**游戏运行时改 `options.txt` 一定会被覆盖，而且写得很频繁：**【源码】

1. **启动时就回写一次**（1.21.11 起 `new Options(...)` 之后紧接着 `options.save()`）
2. **离开设置界面就写**（`OptionsSubScreen.removed()`）
3. **每个滑条/开关改动都写**（`OptionInstance.applyValue()`）
4. F3+H / F3+P 等调试开关立刻写
5. 崩溃恢复、全屏报错等路径也写

所以：**写入前必须确认游戏已退出。**

其它要求：

* **UTF-8 无 BOM**；换行沿用原文件（Windows 上是 CRLF）；保留末尾换行。
* **保留未知行与顺序**：逐行读原文，只就地替换需要的 `key_` 行。
  **不要改 `version:`。**
* **写回用「临时文件 + 原子替换」**，避免中途失败留下半个文件。
* **写后回读校验**，确认真的生效了。
* **键值合法性自校验**，白名单形如 `^key\.(keyboard|mouse|scan)\.[A-Za-z0-9._-]+$`。
* 备份**放在工具自己的工作目录**，不要放进游戏目录（避免被扫描或被网盘抢句柄）。

## 六、为什么不用符号链接共享 options.txt

这是社区里常见的「土办法」，但坑很多：

1. **MC 退出/保存时会整份重写文件**，而且**只写自己认识的值** —— 一次「没装小地图的启动」
   就能把主档里的模组键位全删掉。这正是 **Remember My Txt** 这个 Mod 存在的唯一理由。
2. **原子替换会断开符号链接**：很多工具（含部分启动器）用「写临时文件再替换」的方式保存，
   替换之后就变成两个独立文件了，链接静默失效。Windows 硬链接同理。
3. **FAT/exFAT 不支持符号链接与硬链接**，U 盘/移动硬盘上的实例直接失败。
4. **跨版本共享会互相污染**：Minecraft Wiki 明确说最新版的 `options.txt` **不向下兼容**，
   旧版本在同一目录启动可能把设置**整份重置**。
5. **不同整合包模组集合不同**，必然产生「孤儿键位」互删。
6. **同功能不同 Mod 的名字与默认键本来就不同**，纯文件共享解决不了功能对齐。

**正确做法是共享「键位档案」而不是共享「文件」** —— 这正是本项目的做法。

---

## 七、少数 Mod 把快捷键存在自己的配置里

调研确认存在的：

| Mod / 载体 | 位置 | 格式 |
|---|---|---|
| **Wurst7** | `<游戏目录>/wurst/keybinds.json` | JSON，键名就是 `InputConstants` 标识 | 
| **Meteor Client** | `<游戏目录>/meteor-client/*.nbt` | NBT，每个模块存自己的键位 |
| **OptiFine** | `<游戏目录>/optionsof.txt` | `key_of.key.zoom:46`，旧式数字键码 |
| **Forge / NeoForge** | 仍在 `options.txt`，但值是扩展语法 `key.keyboard.c:SHIFT` | |
| DefaultOptions / YOSBR 类 | `config/defaultoptions/options.txt`、`config/yosbr/options.txt` | **模板**（首次启动复制），不是运行时状态 |

而 **JEI、Xaero's Minimap、Iris、Create/Ponder、Apotheosis** 等**仍然走原版 `KeyMapping`**，
按键就在 `options.txt` 里（有实测样本为证）。**【实测】**

所以「只同步 `options.txt`」覆盖了绝大多数情况，但不是全部 —— 本项目的
「模组配置文件」标签页就是为剩下那部分准备的。
